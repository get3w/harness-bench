# HB-06 分阶段真实验收

执行顺序和标记含义见 [计划入口](README.md)。当前 Get3W 仅支持 OpenCode；
阶段 A、B 优先执行，阶段 C 和 D 的准备可独立推进。阶段 E 按 Harness 分别解锁，
阶段 F 不能提前执行。以下均为未完成任务，文档调整不代表实际运行已经通过。

## 阶段 A：OpenCode 原生闭环【不依赖 Get3W 集成】

前置条件：Docker daemon 可用，OpenCode 发行物许可已核查，真实模型和成本上限已明确。

- [ ] 固定 OpenCode 版本、发行物摘要和任务执行环境。
- [ ] 固定 provider endpoint/revision、模型参数、请求/输出预算和超时。
- [ ] 构建原生运行镜像及原创任务可信评分镜像。
- [ ] 验证模型网关可达、不可绕过、usage 完整和敏感凭据隔离。
- [ ] 先运行少量原创任务，验证真实 CLI、终态、评分、超时和进程清理。
- [ ] 再运行原创 smoke12，归档逐任务结果和原始轨迹。

完成条件：真实运行闭环可复核，失败分类正确、证据完整、无残留进程。
原创任务结果只证明集成测试基础链路，不能作为通用能力结论。

## 阶段 B：OpenCode Get3W 闭环与阶段验收【仅 OpenCode】

前置条件：阶段 A 完成；当前 OpenCode 产品接口可用；HB-03 隔离启动器已实现。

- [ ] 配置隔离 Get3W Server/engine、workspace、状态和真实 Bench bridge。
- [ ] 核查原生/Get3W 使用同一 OpenCode 发行物、模型、任务锁和预算。
- [ ] 核查工具、权限、profile 和环境可比；不等价项明确记录，不能强判能力等价。
- [ ] 原创 smoke12：原生/Get3W 各运行一次，核查输出、事件、模型用量和最终 transcript。
- [ ] 原创 regression60：配对重复，检查失败分类、证据身份和控制器稳定性。
- [ ] 实现并运行 OpenCode 的全部 11 项真实桌面契约，保存断言、截图和日志。
- [ ] 人工复核异常样本并归档 OpenCode 闭环/桌面阶段报告。
- [ ] 阶段 D 的代表性能力任务就绪后，运行 OpenCode 同版原生/Get3W 能力配对及统计验收。

完成条件：闭环与桌面验收覆盖 OpenCode；能力验收另须代表性任务、足够样本和非劣效结果。
报告明确标注仅覆盖 OpenCode。DeepSeek/Pi 集成项继续保留未执行，整体发布不能标为通过。
现有 `compare` 的 `release_verdict` 是三 Harness 整体门禁，阶段报告不绕过它。

## 阶段 C：DeepSeek、Pi 原生基线【不依赖 Get3W 集成】

前置条件：对应 Harness 的发行物许可、固定版本、真实模型配置和运行环境已准备。
两个 Harness 可分别完成，不等待阶段 B 或 Desktop 的多 Harness 改造。

- [ ] DeepSeek：构建固定发行物镜像，验证 Cordis/provider 配置、CLI、JSON 终态与 usage。
- [ ] DeepSeek：少量原创任务后运行 smoke12/regression60，验证执行与评分链路。
- [ ] Pi：构建固定发行物镜像，验证 provider 配置、CLI、JSON 终态与 usage。
- [ ] Pi：少量原创任务后运行 smoke12/regression60，验证执行与评分链路。
- [ ] 分别归档原生基线的版本、配置、任务锁、预算、结果和轨迹。

完成条件：两个原生目标各自真实可运行；对应配置只有 `native`，不启用 `deepseek-get3w` 或
`pi-get3w`。此阶段不提供这两个 Harness 的 Get3W 集成损失结论。

## 阶段 D：授权能力任务与三 Harness 原生比较【不依赖 Get3W 集成】

授权/评分器准备可立即开展；真实比较需要阶段 A/C 的对应原生目标可用。

- [ ] 确认合法能力任务源、授权证据与固定提交；授权未通过不导入。
- [ ] 适配官方真实评分 ABI，用正确解、空解和失败样本核验。
- [ ] 生成完整通用能力任务锁，核查代表性、独立性、样本量与统计功效。
- [ ] 同一模型、任务、共同环境和预算下运行三种 Harness 原生目标，保存各自配置差异。
- [ ] 比较成功率、结果质量、耗时、模型用量和失败原因；说明可比性与结论边界。
- [ ] 多模态任务单独锁定和运行，验证原生附件传递与评分，不混入通用统计。

完成条件：取得可复核的真实原生能力基线，能够为选型提供依据。
不得把原创参数变体作为独立真实世界任务，或将 smoke 通过等同能力验收通过。

## 阶段 F：整体发布验收【等待三 Harness 集成验收】

前置条件：OpenCode、DeepSeek、Pi 的能力配对与桌面契约全部就绪，使用同一待验收
Get3W 构建；旧阶段结果来自其他构建或配置时，应重跑受影响项，不能直接拼接为通过。

- [ ] 核查三种 Harness 各自原生/Get3W 同版，模型、锁、环境、配置、预算和证据匹配。
